# 从打包到上线

发布状态按真实进展记录。包装完成、技术检查通过、用户上传、平台审核通过和公开上线分别核实。

| 状态 | 何时记录 | 下一步 |
| --- | --- | --- |
| materials_ready／材料就绪 | 文件和文案准备完成，检查范围已说明 | 交付上传包与逐字段填写信息 |
| submitted_pending_review／已上传待审核 | 用户确认提交，或看到成功回执 | 记录提交日期、证据来源和版本，等审核结果 |
| changes_requested／需修改 | 收到明确退回原因 | 修对应文件，保留旧版，重检重交 |
| approved／审核通过 | 用户确认或平台回执说明通过 | 查看是否需另行发布、是否公开可用 |
| published／已上线 | 用户确认上线或看到公开可用页面 | 记录上线日期及可取得的公开链接 |

信息放在项目的publication.json，最少包括status、reported_on、evidence_type、evidence。已知时才填approved_on、published_on、public_url。证据可为用户反馈或平台回执，标明来源。未知信息为null，不编造。参考 [洛小咪状态记录](../examples/luoxiaomi2/publication.json)。

默认由用户在自己的微信入口提交。交付填写信息、主图与缩略图、横幅、封面、图标、可选赞赏图，对应关系见album.json。页面要求与profile不符时，按当前页面调整副本，重新检查打包。

用户要求助手实际操作平台时，按该次授权和真实工具能力执行，账号登录与验证由用户控制。准备材料本身不代表获得上传或发布授权。

待审核时不自行反复提交。用户提供结果后续接：退回则定点修改；通过但未上线记录通过；公开可用才更新上线。归档保留提交版本、修改原因、回执和最终链接，公开案例排除账号信息等私人数据。
